# Implementation Plan – проект ETL (variant_04, London)

## Общая цель
Построить воспроизводимый, отказоустойчивый и оркестрируемый инкрементальный ETL-пайплайн:  
`API → raw JSON → normalized CSV → mart CSV → PostgreSQL`  
с поддержкой full/incremental загрузки, сквозным стейт-менеджментом, DQ-гейтом на базе Apache Airflow и покрытием unit-тестами.

## Неделя 12 – Финальная оркестрация, Инкрементальность и DQ Gate

### Выполненные задачи
1. Разработан и отлажен финальный файл описания графа `dags/etl_london_weather.py` с расписанием запусков `schedule="*/5 * * * *"` и цепочкой задач:  
   `extract_weather ➔ normalize_data ➔ build_mart ➔ data_quality_checks ➔ load_to_postgres`
2. **Внедрение инкрементальности:** Исключена привязка к системному времени сервера. Каждый запуск графа (DAG Run) изолированно обрабатывает данные за свой логический период времени. Даты динамически передаются в функции `normalize_raw_to_csv` и `build_daily_mart` через Jinja-шаблоны Airflow: `{{ data_interval_start }}` и `{{ data_interval_end }}`. Файлы сохраняются как `mart_YYYY-MM-DD.csv`.
3. **Реализация DQ Gate:** Задача выполнения проверок качества данных `data_quality_checks` интегрирована в общую цепочку строго **перед** задачей загрузки в БД. При возникновении ошибки уровня критичности `FAIL` выполнение DAG останавливается, блокируя шаг `load_to_postgres` и защищая продакшн-таблицы от загрязнения.
4. **Обеспечение Идемпотентности:** Шаг загрузки в модуле `load_incremental.py` переписан по транзакционной стратегии **DELETE period + INSERT**. При аварийном ручном или автоматическом перезапуске (Retry) одной и той же задачи за определенную дату старые строки за этот период каскадно вычищаются из таблицы `weather_london_daily_mart`, после чего вставляются обновленные, гарантируя отсутствие дубликатов.
5. Проведена полная очистка корневой директории проекта от лишних файлов-дубликатов, проведено финальное тестирование пайплайна в UI Airflow, все задачи успешно завершаются с зеленым статусом (`success`).

### Артефакты
- Производственный DAG-файл `dags/etl_london_weather.py`
- Идемпотентный скрипт загрузки `src/load/load_incremental.py`
- Чистый, структурированный финальный репозиторий проекта
