## 5. Алгоритмы расчета бизнес-метрик витрины (KPI)

Переход со слоя `Normalized` на слой `Mart` осуществляется путем применения функций агрегации Pandas (`groupby('date')`):

* `avg_temp` = `mean(normalized.temperature_2m)`
* `min_temp` = `min(normalized.temperature_2m)`
* `max_temp` = `max(normalized.temperature_2m)`
* `avg_humidity` = `mean(normalized.relative_humidity_2m)`
* `total_precip` = `sum(normalized.precipitation)`
* `avg_windspeed` = `mean(normalized.wind_speed_10m)`

## 6. Соглашение об именовании (Naming Conventions)

* **Регистр символов:** Строго `snake_case` для всех названий таблиц, файлов, функций и колонок.
* **Идентификаторы:** Все суррогатные и бизнес-ключи локаций обязаны оканчиваться на суффикс `_id` (например, `city_id`).
* **Временные метки:** Почасовые метки времени именуются строго как `ts`, а календарные дни без указания часов — как `date`.
* **Префиксы агрегаций:** Все расчетные поля витрин обязаны иметь префикс типа агрегации: `avg_`, `min_`, `max_`, `total_`.
* **Запрещенные паттерны:** Не допускается использование неинформативных имен полей (`value`, `metric_1`, `data_new`).

## 8. Спецификация ограничений качества (Data Quality Gate)

Правила валидации, зафиксированные в модуле `src/dq.py`. Нарушение правил уровня `FAIL` полностью блокирует загрузку данных в базу PostgreSQL.

| Валидируемое поле / Объект | Слой данных | Тип проверки | Уровень критичности | Действие при сбое |
| :--- | :--- | :--- | :--- | :--- |
| DataFrame (Общий) | Normalized / Mart | `non_empty` | **FAIL** | Полная остановка пайплайна |
| `ts` / `date` | Normalized / Mart | `not_null` | **FAIL** | Полная остановка пайплайна |
| `city_id` | Normalized / Mart | `not_null` | **FAIL** | Полная остановка пайплайна |
| `temperature_2m` | Normalized | Коридор `[-50.0, 60.0]` | **FAIL** | Блокировка шага Load |
| `precipitation` | Normalized | Проверка `value ≥ 0` | **FAIL** | Блокировка шага Load |
| `ts` + `city_id` | Normalized | `unique` (Без дубликатов) | **FAIL** | Блокировка шага Load |
| `date` + `city_id` | Mart | `unique` (Без дубликатов) | **FAIL** | Блокировка шага Load |
| `min_temp`, `avg_temp`, `max_temp` | Mart | Логика: `min ≤ avg ≤ max` | **FAIL** | Блокировка шага Load |
| `wind_speed_10m` | Normalized | Лимит аномалий `value < 150` | **WARNING** | Запись в лог, пропуск шага |

## 9. Инфраструктурный контракт (Недели 11-12)

* **Инструмент оркестрации:** Apache Airflow 2.8.1 (LocalExecutor).
* **Контейнеризация:** Docker Desktop (Windows) / Docker Compose.
* **Целевое Production-хранилище:** PostgreSQL 13.
* **Параметры сетевого подключения:** * Host во внутренней сети Docker: `postgres`  
  * Внутренний порт сети контейнеров: `5432`  
  * Проброшенный внешний порт для хоста Windows: `5434`  
  * Имя базы / Логин / Пароль: `airflow` / `airflow` / `airflow`  
* **Политика инкрементальности:** Выделение временных интервалов на основе системного контекста Airflow (`{{ data_interval_start }}` и `{{ data_interval_end }}`). Исключено использование локального времени сервера.
* **Принцип Идемпотентности загрузки:** Шаг `load_to_postgres` обязан гарантировать неизменность целевой таблицы при повторных перезапусках (Retry) таски за аналогичный логический интервал времени. Стратегия выполнения: атомарный **DELETE** записей за целевой период перед процедурой **INSERT**.
